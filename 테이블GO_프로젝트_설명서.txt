테이블GO 프로젝트 설명서
(비개발자를 위한 쉬운 설명)
작성일: 2026-08-12


===================================
1. 테이블GO가 뭔가요?
===================================

테이블GO는 식당 테이블을 예약할 수 있는 작은 웹 서비스입니다.
크게 두 개의 화면(웹사이트)으로 이루어져 있습니다.

  1) 손님용 예약 사이트
     주소: https://table-go-nine.vercel.app
     - 누구나 로그인 없이 들어와서 날짜와 시간을 골라 예약할 수 있습니다.
     - 영업시간은 10:00~22:00, 2시간 단위로 하루에 6개 시간대가 있습니다.
     - 토요일, 일요일은 자동으로 휴무 처리됩니다.

  2) 사장님(직원)용 관리자 페이지
     주소: https://table-go-admin.vercel.app
     - 로그인을 해야 들어갈 수 있는 내부 관리 화면입니다.
     - 오늘/전체 예약 현황을 확인하고, 예약을 취소할 수 있습니다.

두 사이트는 화면 오른쪽 위/아래에 있는 "관리자 로그인", "예약 사이트 보기"
버튼으로 서로 연결되어 있어서, 손님용 사이트에서 관리자 사이트로,
관리자 사이트에서 손님용 사이트로 바로 이동할 수 있습니다.


===================================
2. 오늘 새로 만든 / 고친 기능
===================================

(1) 실시간 예약 현황 업데이트
    - 예전에는 예약 페이지를 새로고침해야 다른 사람이 방금 예약했는지
      알 수 있었습니다.
    - 이제는 새로고침 없이도 3초마다 자동으로 확인해서,
      다른 손님이 그 시간대를 예약하면 버튼이 즉시 "마감"으로 바뀌고,
      예약이 취소되면 다시 "예약 가능"으로 바뀝니다.
    - 달력에서도 하루 6개 시간대가 전부 찼으면 "마감" 표시가 뜹니다.

(2) 중복 예약 방지
    - 두 사람이 동시에 같은 시간대를 예약 버튼을 누르는 극단적인 상황을
      대비해서, 서버(데이터를 저장하는 컴퓨터)에서 저장하기 직전에
      "이 시간, 진짜 아직 비어있나?"를 한 번 더 확인합니다.
    - 그래도 정말 딱 동시에 눌렀을 경우를 대비해서, 데이터베이스
      (예약 정보가 저장되는 곳) 자체에도 "같은 날짜·같은 시간대는
      한 팀만 예약 가능"이라는 규칙을 걸어놨습니다. 이 규칙 덕분에
      어떤 경우에도 이중 예약이 물리적으로 불가능합니다.
    - 만약 두 사람이 거의 동시에 눌렀다면, 늦게 누른 사람에게는
      "죄송합니다. 해당 시간은 방금 예약되었습니다. 다른 시간대를
      선택해주세요." 라는 안내 메시지가 뜹니다.
      (실제로 두 개의 브라우저 창을 열어놓고 동시에 예약을 눌러서
      테스트했고, 정확히 한 건만 저장되는 것을 확인했습니다.)

(3) 손님용 사이트 ↔ 관리자 사이트 연결
    - 예전에는 두 사이트가 서로 아무 연결 고리 없이 따로 놀았습니다.
    - 손님용 사이트 상단에 "관리자 로그인" 버튼을 추가해서 직원이
      바로 관리자 페이지로 이동할 수 있게 했습니다.
    - 관리자 페이지에는 "예약 사이트 보기" 버튼을 추가해서 직원이
      손님 화면이 어떻게 보이는지 바로 확인할 수 있게 했습니다.

(4) 인터넷에 실제로 배포 (포트폴리오용)
    - 지금까지는 이 프로그램이 내 컴퓨터 안에서만 실행되고 있었습니다
      (개발자들은 이걸 "로컬"이라고 부릅니다).
    - 오늘 아래 두 가지 작업을 거쳐서 누구나 인터넷에서 접속할 수
      있는 실제 서비스로 만들었습니다.
      ① GitHub(깃허브)에 코드 올리기
         - GitHub는 프로그램 코드를 저장하고 관리하는 서비스입니다.
           "이 프로그램을 어떻게 만들었는지" 그 재료(소스 코드)를
           보관하는 창고라고 생각하시면 됩니다. 포트폴리오에서
           코드 저장소 링크로 보여줄 수 있습니다.
         - 저장 위치: https://github.com/djdw2657/table-go
      ② Vercel(버셀)에 배포하기
         - Vercel은 GitHub에 올려둔 코드를 실제로 인터넷에서 접속
           가능한 웹사이트로 "켜주는" 서비스입니다.
         - 배포 과정에서 실제 서버 환경에서만 발생하는 문제를
           몇 가지 발견해서 고쳤습니다 (자세한 내용은 4번 참고).

3. 어떤 기술로 만들었나요? (쉬운 비유로)
===================================

- Next.js (넥스트.js)
  화면(버튼, 글자, 달력 등)을 그리고 사용자 요청을 처리하는 핵심
  뼈대입니다. 레스토랑으로 치면 '주방+홀 운영 시스템' 같은 것입니다.

- 데이터베이스 (Neon / Postgres)
  예약 정보, 시간대 정보가 실제로 저장되는 곳입니다. 손님 정보와
  예약 내역이 적힌 '장부'라고 보시면 됩니다.

- Prisma (프리즈마)
  프로그램이 저 '장부'(데이터베이스)를 안전하고 정확하게 읽고
  쓰도록 도와주는 도구입니다.

- Clerk (클럭)
  관리자 페이지의 로그인 기능을 담당합니다. 아이디/비밀번호를
  직접 관리하는 대신 검증된 외부 서비스를 빌려 쓰는 방식입니다.

- 모노레포 (Monorepo)
  이 프로젝트 하나 안에 손님용 사이트, 관리자 사이트 등 여러 개의
  작은 프로그램이 함께 들어있는 구조입니다. 각각 따로 만드는 대신
  공통으로 쓰는 부품(디자인, 데이터베이스 연결 등)을 한 곳에 모아
  같이 관리해서 효율적입니다. next-forge라는 이름의 완성된 뼈대
  (템플릿)를 기반으로 시작했습니다.

- GitHub / Vercel
  위 2번에서 설명한 대로, 코드 보관(GitHub)과 실제 서비스로 켜기
  (Vercel) 담당입니다.

4. 배포하면서 실제로 겪은 문제와 해결 (참고용)
===================================

인터넷에 실제로 서비스를 켜는 과정에서, 내 컴퓨터에서는 멀쩡히
되던 것이 실제 서버에서는 안 되는 경우가 몇 번 있었습니다.
개발에서 흔히 있는 일이며, 하나씩 원인을 찾아 고쳤습니다.

  - 블로그/약관 페이지가 예약 기능과 무관한 외부 콘텐츠 서비스
    (BaseHub)에 연결되어 있었는데, 그 서비스 계정을 만들지 않아서
    배포가 막혔습니다. → 예약 기능에 필요 없는 페이지라 삭제했습니다.

  - 관리자 페이지 로그인 화면 관련 코드에 오래된 버그가 있어서
    실제 배포 시 빌드가 실패했습니다. → 코드를 수정해서 해결했습니다.

  - 예약 페이지가 실제 서버에서 데이터베이스에 접속할 때 사용하던
    연결 방식(웹소켓)이 불안정해서 오류가 났습니다. → 더 안정적인
    연결 방식(HTTP)으로 바꿔서 해결했습니다.

  - 두 개의 사이트(손님용/관리자용)가 서로의 정확한 인터넷 주소를
    몰라서 "관리자 로그인", "예약 사이트 보기" 링크가 깨져있었는데,
    실제 배포된 주소로 값을 넣어줘서 해결했습니다.


===================================
5. 앞으로 더 추가하면 좋을 기능 (아이디어)
===================================

- 예약 시 문자/카카오톡 알림 보내기
- 관리자 페이지에서 날짜별 매출/통계 보기
- 예약 취소를 손님이 직접 할 수 있게 하기 (지금은 관리자만 취소 가능)
- 나만의 인터넷 주소(도메인) 연결하기 (예: tablego.com)
